- Инициировать начисление штрафа() - планировщик запускает процедуру начисления штрафов: вызывает Начислить штраф() по расписанию ежедневно.

- Показать форму изменения продукта() - открывает форму редактирования продукта (изменение параметров, сохранение через Обновить кредитный продукт()), с проверкой прав.

**Класс** **Работа с БД**

Методы:

- Подтвердить кредит() - фиксирует в БД факт подтверждения кредита (клиент подписал договор), меняет статус.

- Авторизация() - проверяет учетные данные пользователя: ищет пользователя в БД, сверяет пароль, возвращает результат (успех/ошибка).

- Регистрация() - создаёт нового клиента в БД: сохраняет профиль, логин, хэш пароля, стартовые статусы; проверяет уникальность.

- Начислить проценты() - выполняет начисление процентов по активным кредитам: рассчитывает сумму за период, добавляет транзакцию, обновляет задолженность.

- Начислить штраф() - Начисляет штрафы по просрочкам: находит просроченные платежи, считает сумму штрафа, записывает транзакцию и обновляет состояние кредита.

- Создать заявку() - создаёт заявку на кредит в БД: сохраняет параметры, устанавливает начальный статус.

- Одобрить заявку() - переводит заявку в статус «одобрено», инициирует создание кредита Создать кредит().

- Отклонить заявку() - переводит заявку в статус «отклонено».

- Создать кредит() - создаёт сущность кредита на основе одобренной заявки.

- Создать кредитный продукт() - добавляет в БД новый кредитный продукт.

- Обновить кредитный продукт() - изменяет параметры существующего продукта.

- Удалить кредитный продукт() - удаляет кредитный продукт.

- Получить данные для отображения() – обобшение всех методов, которые выдают набор данных, требуемых для отображения форм.

Файл lending.jar — основной исполняемый артефакт прикладного уровня, обеспечивающий работу системы и доступ к данным. Данный файл представляет собой Java‑приложение и включает в себя прикладную часть и интеграционный слой.

Прикладная часть: скомпилированные Java‑классы, реализующие бизнес‑логику, обработку операций и взаимодействие с хранилищем данных.

Интеграционный слой: компоненты доступа к данным (драйвер/клиент), обеспечивающие подключение к СУБД и выполнение запросов к базе данных по интерфейсу isql.

Артефакты, функционирующие в рамках базы данных PostgreSQL (Database server), включают в себя исполняемое программное обеспечение DBMS PostgreSQL, структуру базы данных, представленную таблицами: client, manager, manager\_specialization, credit, credit\_category, credit\_product, application, transaction

### 2.3.4 Модель размещения артефактов

Модель размещения артефактов системы представлена на рисунке 26.

![rasm\_art.jpg](assets/images/image27.jpeg)

Рисунок  26 - Модель размещения артефактов проектируемой системы

Проектируемая программно информационная система развертывается в виде нескольких устройств:

- Менеджер — рабочая станция сотрудника (оператора), работающего с системой.

- Клиент — рабочая станция конечного пользователя (заемщика), взаимодействующего с системой.

- Сервер кредитования / сервер приложения — сервер, на котором исполняется основная логика системы.

- Сервер базы данных — выделенный сервер для хранения и управления данными.

На каждом узле размещаются артефакты соответствующего назначения:

На устройствах Менеджер и Клиент размещается артефакт «Браузер», выступающий в роли тонкого клиента.

На сервере кредитования размещена система «Система кредитования» в виде исполняемого артефакта lending.jar, который реализует прикладную логику

На сервере базы данных размещено ПО типа СУБД — PostgreSQL, в рамках которого функционирует база данных со структурой таблиц, отражающих предметную область кредитования.

Узлы находятся в сети и обмениваются данными по специализированным протоколам:

Взаимодействие между рабочими станциями (Менеджер/Клиент) и сервером кредитования осуществляется по протоколу HTTP, что позволяет пользователям работать с системой через веб-интерфейс в браузере.

Взаимодействие между сервером кредитования и сервером базы данных (PostgreSQL) осуществляется по интерфейсу isql (SQL доступ), обеспечивая выполнение запросов и обмен данными между приложением и таблицами базы данных.
