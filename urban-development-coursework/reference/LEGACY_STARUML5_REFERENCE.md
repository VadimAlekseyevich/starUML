# Как использовать lending/Костыль после перехода на StarUML 7

## Используем как образец

Переносим из старой работы:

- смысл диаграмм;
- уровень детализации;
- декомпозицию;
- отношения;
- Documentation;
- визуальную композицию;
- связь между этапами.

## Не копируем автоматически

Не считаем методическим требованием:

- XPD/XML;
- `#OwnedElements`;
- `XPD:REF`;
- legacy `*View` classes;
- `ActivityGraph/TOP` как обязательный storage;
- пустые Component/Deployment Main;
- странное размещение диаграмм в старом дереве;
- ограничения старого UI.

## Принцип

Если особенность подтверждает METHOD — сохраняем.

Если она есть только в старом XPD и выглядит как техническая особенность StarUML 5 — в StarUML 7 выбираем естественное современное представление.

## Примеры

### Worker

Сохраняем UML Class + worker/caseWorker, потому что это подтверждается методичкой.

### ActivityGraph

Не обязаны повторять XPD `ActivityGraph → TOP`. Сохраняем Activity-семантику.

### Class Packages / Detail / Relations

Сохраняем три представления, потому что это прямо требует METHOD, а lending показывает практический пример их оформления.

### Component/Deployment placement

Смотрим lending как образец содержимого, но не обязаны помещать диаграмму в тот же legacy package, если методичка этого не требует.
