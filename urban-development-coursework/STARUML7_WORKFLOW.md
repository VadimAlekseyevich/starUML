# Рабочий процесс StarUML 7

## Канонический проект

Текущий рабочий файл:

`01_functionality/urban_development_functionality.mdj`

Он является единственным редактируемым источником UML-модели.

Пока имя отражает происхождение из первой работы. Когда в этом же проекте появятся алгоритмы, классы, компоненты и deployment, при необходимости можно один раз перенести/переименовать файл. Поддерживать два параллельных рабочих `.mdj` нельзя.

## Запуск

Из корня репозитория:

`run_coursework.bat`

BAT:

1. выполняет `git pull --ff-only`;
2. находит единственный `.mdj` в `urban-development-coursework`;
3. открывает его в StarUML 7.

## Источники истины

### UML-модель

`.mdj` хранит model elements, `_id`, отношения, диаграммы, Views и Documentation.

### Методика

`methodology/` отвечает на вопрос: **что должен показать курс UML**.

### Эталон

`lending.uml`, `Костыль/` и `reference/` отвечают: **как похожая работа была оформлена и детализирована**.

Они не задают современный формат хранения.

## Что больше не делаем в обычной работе

Не нужно:

- редактировать `fragments/*.xml`;
- пересчитывать XPD collections;
- чинить `XPD:REF`;
- собирать `dist/urban_development.uml`;
- создавать сначала StarUML 5 XML, а потом импортировать его в StarUML 7.

Эти файлы заморожены как legacy/reference.

## Проверка любого изменения

Перед завершением диаграммы проверяем:

1. **METHOD** — соблюдена методичка?
2. **MODEL** — согласовано с предыдущими UML-диаграммами?
3. **PROJECT** — соответствует реальному Urban Development Generator?
4. **TOOL** — корректно ли это выражено средствами StarUML 7?

Первые три пункта определяют содержание. Четвёртый — только реализацию в редакторе.

## Git

Перед работой:

```bat
git pull --rebase origin main
```

После сохранения:

```bat
git add urban-development-coursework
git commit -m "Update coursework model"
git push origin main
```

Force push для обычной работы не использовать.
