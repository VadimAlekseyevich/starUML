# Methodology — требования из методички

Основной источник: `/методичка.docx`.

Автоматически извлечённый первичный слой находится в `methodology/source/`.

- `methodology-extract.md` — текст с P-идентификаторами;
- `methodology-index.json` — структурированный индекс;
- `media/` — рисунки.

## Ключевое правило после перехода на StarUML 7

**Замечания и требования методички сохраняем. Инструментальные детали StarUML 5 — переосмысливаем.**

Остаются обязательными смысловые правила:

- Actor vs внутренний worker;
- include/extend;
- основная + декомпозиционные Use Case;
- текстовые потоки;
- Activity как реализация Use Case;
- содержательные guards вместо «Да/Нет»;
- Documentation;
- boundary/control/entity;
- три представления Class Model;
- Sequence message ↔ Class operation.

Если методичка говорит «в StarUML 5 создать ActivityGraph/TOP» или описывает старую панель свойств, это считается **историческим способом реализации требования**, а не требованием хранить XPD.

В StarUML 7 воспроизводим UML-смысл средствами современного редактора.

## Покрытие

- Use Case — P0061–P0177;
- Activity — P0178–P0276;
- State Machine — P0277–P0316;
- Class — P0317–P0454;
- Sequence — P0455–P0512.

Отдельных глав Component/Deployment в DOCX нет. Эти этапы опираются на `lending.uml` [LENDING] и реальную архитектуру проекта [PROJECT].

## Маркеры

- `METHOD` — прямо из методички;
- `LENDING` — старый эталон;
- `COURSEWORK` — Костыль/материалы;
- `PROJECT` — реальный urban-development-generator;
- `UML` — общая нотация;
- `WORKING` — наше инженерное решение.

Версия StarUML не является самостоятельным методическим источником.
