# Methodology — требования из методички

Основной методический источник теперь хранится в корне репозитория как `методичка.docx`.

DOCX автоматически распаковывается workflow-ом в `methodology/source/`:

- `methodology-extract.md` — последовательный текст с идентификаторами абзацев;
- `methodology-index.json` — структурированный индекс;
- `media/` — изображения из документа.

Правила трассировки описаны в `TRACEABILITY.md`.

## Покрытие методички

В текущем DOCX явно выделены темы:

- диаграмма прецедентов — примерно P0061–P0177;
- диаграмма деятельности — P0178–P0276;
- диаграмма автомата — P0277–P0316;
- диаграмма классов — P0317–P0454;
- диаграмма последовательности — P0455–P0512.

Отдельных учебных глав про Component Diagram и Deployment Diagram в этом DOCX нет. Поэтому файлы `components.md` и `deployment.md` основаны прежде всего на `lending.uml` и реальной архитектуре Urban Development Generator и **не должны маркироваться как прямые требования METHOD**.

## Маркеры происхождения

- `METHOD` — прямо следует из `методичка.docx`;
- `LENDING` — подтверждено структурой `lending.uml`;
- `COURSEWORK` — подтверждено материалами из `Костыль`;
- `PROJECT` — следует из реального `urban-development-generator`;
- `UML` — общее правило нотации UML;
- `WORKING` — наше инженерное соглашение для совместимости и сборки.

## Порядок курсовой

`Порядок.txt` задаёт пять крупных этапов:

1. модель функциональности;
2. модель алгоритмов;
3. модель классов;
4. модель компонентов;
5. модель размещения.

Методичка детализирует первые три этапа и поведенческие диаграммы; component/deployment восстанавливаются по эталону `lending.uml`.
