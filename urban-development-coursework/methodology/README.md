# Methodology — рабочие правила курсовой

Этот раздел отделяет **семантические требования** от технического XML StarUML.

## Маркеры происхождения правила

- **[METHOD]** — следует из методических указаний/официального методического обеспечения дисциплины.
- **[LENDING]** — подтверждено структурой `lending.uml`.
- **[COURSEWORK]** — подтверждено изображениями/материалами из `Костыль`.
- **[PROJECT]** — следует из реальной предметной области `urban-development-generator`.
- **[WORKING]** — наше рабочее правило для обеспечения согласованности; может уточняться.

Это важно: мы не будем выдавать наше удобное соглашение за прямое требование преподавателя.

## Порядок из Порядок.txt

1. Разработка модели функциональности системы.
2. Разработка модели алгоритмов системы.
3. Разработка модели классов системы.
4. Разработка модели компонентов системы.
5. Разработка модели размещения системы.

Файлы этого раздела построены по этим пяти этапам.

## Дополнительные диаграммы

Официальное методическое обеспечение дисциплины отдельно перечисляет Use Case, Class и Activity Diagram как лабораторные работы, а Communication и Sequence Diagram — как практические занятия. Поэтому Interaction/Statechart не игнорируем: они могут понадобиться как детализация, даже если в `Порядок.txt` названы более крупные «модели».
