# 3. Модель классов

## Основание

**[METHOD]** Class Diagram указана как лабораторная работа № 11.

**[LENDING]** В эталоне 13 Class Diagram. Особенно важны серии `Packages → DetailClass → DetailClassWithRelation`, а также отдельные `ControlClass` и `BoundaryClass`.

Следовательно, преподавательский эталон явно предполагает **несколько уровней представления классов**.

## Рабочая структура

**[WORKING]** Для Urban Development планируем минимум:

1. **ClassPackages** — укрупнённые пакеты/подсистемы классов.
2. **EntityClasses** — предметные/долгоживущие сущности.
3. **EntityClassesWithRelations** — связи, кратности, агрегации/композиции/наследование.
4. **ControlClasses** — координация сценариев использования.
5. **BoundaryClasses** — точки взаимодействия с пользователем/внешними интерфейсами.

Не обязательно повторять названия lending буквально; повторяется принцип декомпозиции.

## Источник классов

**[PROJECT]** Доменную модель нельзя автоматически получить простым копированием Python-файлов. Код содержит инфраструктурные адаптеры, DTO и технические классы, которые не всегда нужны в проектной UML-модели.

Основные кандидаты предметных классов:

- Project;
- DataLayer / DataSource;
- Scenario;
- Run;
- TerritorySnapshot;
- Constraint / ValidationReport;
- RoadNetwork;
- Block / Parcel;
- Building;
- InfrastructureFacility;
- Metric / MetricResult;
- Artifact.

## Согласованность
