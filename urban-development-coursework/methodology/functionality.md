# 1. Модель функциональности

## Что требуется

Use Case — функция/задача/работа, реализуемая процессом [METHOD: P0063–P0066]. Use Case Diagram моделирует функциональность системы [METHOD: P0098].

**Модель функциональности = основная Use Case Diagram + декомпозиции + текстовые сценарии.**

## Именование

Use Case называется процессом, а не данными, результатом, событием или условием [METHOD: P0092].

Хорошо:

- «Создать проект»;
- «Настроить сценарий развития»;
- «Запустить сценарий развития»;
- «Экспортировать результаты».

## Actor и worker

Actor — внешняя сущность [METHOD: P0073].

Человек, являющийся частью системы и выполняющий её функциональность, моделируется как worker [METHOD: P0121–P0124].

P0125–P0135 показывают это в старом StarUML 5 как Class + stereotype `worker`. В StarUML 7 сохраняем **семантику**, а не старый UI: `ГИС-аналитик` остаётся UML Class со stereotype worker/caseWorker.

## Отношения

Actor ↔ Use Case: Association [METHOD: P0080–P0082].

Use Case ↔ Use Case: include / extend / generalization; Association между Use Case не используется [METHOD: P0078–P0082].

- include — безусловная часть [METHOD: P0083–P0085];
- extend — условная часть [METHOD: P0084–P0085];
- у extend должно быть содержательное условие [METHOD: P0161–P0163].

## Основная диаграмма

Модель должна иметь одну основную диаграмму и декомпозиции [METHOD: P0102–P0103].

Обычно на первом уровне 3–9 относительно независимых функций [METHOD: P0104].

На основной диаграмме не нужно частично раскладывать эти функции include/extend; декомпозиция выносится отдельно [METHOD: P0105–P0107].

## Декомпозиция

Детальная диаграмма должна содержать декомпозируемый Use Case как логический центр [METHOD: P0112].

Для Use Case первого уровня нужны декомпозиции [METHOD: P0138–P0141].

## Текстовые потоки

Для базовых Use Case нужны описания поведения [METHOD: P0099].

Формат:

- main flow;
- `A...` alternatives;
- `S...` subflows;
- `E...` errors [METHOD: P0165–P0174].

Также нужны actor scenarios [METHOD: P0108–P0109; P0143–P0145].

## Documentation

Все узлы и связи должны иметь пояснения [METHOD: P0149–P0153].

Связь include/extend документируется с объяснением выбора типа [METHOD: P0159–P0163].

## Текущий Urban Development

Канонический проект:

`../01_functionality/urban_development_functionality.mdj`

Основная диаграмма:

- `UrbanDevelopment`.

Use Case первого уровня:

1. Создать проект;
2. Управление исходными геоданными;
3. Настроить сценарий развития;
4. Запустить сценарий развития;
5. Просмотр и сравнение сценариев;
6. Экспортировать результаты.

Декомпозиции:

- `ProjectCreation`;
- `DataManagement`;
- `ScenarioConfiguration`;
- `ScenarioLaunch`;
- `ScenarioComparison`;
- `ResultExport`.

`GenerationExecution` детализирует внутренний процесс генерации.

## Критерий завершённости

Нужны согласованные model identities (`_id` в StarUML 7), декомпозиции, реальные conditions, Documentation и текстовые потоки.

Первая работа этому базовому критерию соответствует.
