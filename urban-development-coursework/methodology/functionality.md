# 1. Модель функциональности

## Что считаем моделью функциональности

**[METHOD]** В методическом обеспечении дисциплины Use Case Diagram выделена отдельными лабораторными работами № 9–10.

**[LENDING]** В `Use Case View` эталона существует 8 Use Case Diagram: одна AS IS и семь внутри TO BE, включая общую и функционально специализированные схемы.

Отсюда рабочая трактовка первого пункта `Порядок.txt`: **модель функциональности = система диаграмм прецедентов**, а не одна диаграмма.

## Уровни

**[WORKING]**

- Обзорная схема показывает границы функциональности и основных акторов.
- Детальные схемы раскрывают крупные функциональные области.
- Один и тот же прецедент, повторённый на нескольких схемах, остаётся одной сущностью и имеет один GUID.
- Детальные операции не должны произвольно менять название при переходе к Activity/Class/Sequence.

## include и extend

**[LENDING]** Эталон активно использует оба типа связей.

**[WORKING]**

- `include` — базовый прецедент всегда использует включаемую функцию как часть реализации;
- `extend` — дополнительное поведение возникает при условии/варианте сценария.

Не выбирать связь только ради визуального сходства с lending. Сначала формулируется смысл, потом тип UML-связи.

## Текущая Urban Development модель

Обзорная диаграмма:

- `UrbanDevelopment`.

Детальные:

- `ProjectCreation`;
- `DataManagement`;
- `ScenarioConfiguration`;
- `ScenarioLaunch`;
- `GenerationExecution`.

Следующий шаг функциональной модели — проверить, достаточно ли отдельной диаграммы для сравнения сценариев/результатов. Решение принимается по сложности Use Case и по структуре пояснительной записки, а не по желанию довести число схем до lending.

## Проверка перед сдачей

- у каждого актора понятна внешняя роль;
- названия Use Case сформулированы как действия/цели;
- общая диаграмма не перегружена мелкими деталями;
- детальные диаграммы не создают дубликаты сущностей;
- include/extend имеют объяснимый смысл;
- имена совпадают с `model/registry.yaml`;
- ключевые нетривиальные Use Case имеют кандидатов на последующую алгоритмическую детализацию.
