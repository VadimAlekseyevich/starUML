# Interaction diagrams: Sequence / Communication

Эти диаграммы не выделены отдельным пунктом `Порядок.txt`, но в официальном методическом обеспечении дисциплины Communication Diagram указана для практического занятия № 9, а Sequence Diagram — для занятий № 10–11.

**[LENDING]** В `lending.uml` существует одна `UMLSequenceDiagram` внутри пакета `Interface`.

## Когда добавляем Sequence

Когда важно объяснить временной порядок вызовов между несколькими объектами/подсистемами.

Лучший кандидат в нашем проекте:

`Пользователь → Frontend → Backend → очередь/Worker → Core → PostGIS → Worker → Backend → Frontend`

для запуска генерации и получения результата.

## Согласованность

Участники Sequence Diagram должны происходить из уже зафиксированных классов/компонентов. Sequence не вводит параллельную архитектуру с новыми случайными именами.
