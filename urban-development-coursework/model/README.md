# Canonical model registry

Этот каталог — единый словарь имён и идентичностей нашей UML-модели.

## registry.yaml

Содержит уже существующие GUID верхних View, акторов, Use Case, Use Case Diagram и include/extend. Если элемент уже есть здесь, новая диаграмма должна ссылаться на существующую сущность, а не создавать «почти такую же».

## use_cases.yaml

Показывает текущую декомпозицию по диаграммам. Файл удобен для проверки, что обзорная и детальные схемы используют одинаковые объекты.

## architecture.yaml

Канонические названия будущих компонентов/узлов взяты из реального `urban-development-generator`, а не придуманы специально для картинки.

## Правило изменения имени

Переименование сущности — модельное изменение. Оно должно выполняться одновременно в registry, XML-модели, документации и связанных диаграммах. Нельзя переименовать только подпись на одной картинке.
