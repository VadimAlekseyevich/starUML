# Urban Development Coursework — UML workspace

Эта папка — рабочая система для курсового проекта по дисциплине «Проектирование информационных систем».

Цель — не редактировать большой StarUML-файл вслепую, а хранить рядом:

- первичные эталоны из `lending.uml`;
- правила, извлечённые из методических материалов и эталонной курсовой;
- канонический реестр сущностей Urban Development Generator;
- безопасные сборочные фрагменты;
- скрипты сборки и валидации;
- итоговый монолитный `.uml`, который открывается в StarUML.

## Приоритет источников

Если источники расходятся, используем такой порядок:

1. **Методические указания Белова В.В. и Чистяковой В.И.** — что требуется семантически.
2. **`lending.uml`** — как это реально оформлено в StarUML у эталонной работы.
3. **`Костыль/диаграммы` и документы курсовой** — как результат выглядит на рисунках и в пояснительной записке.
4. **`urban-development-generator`** — предметная область и реальные сущности нашей системы.
5. Общие правила UML — только если первые четыре источника не дают ответа.

## Структура

- `reference/` — разобранный `lending.uml`: каталог схем, изображения и точные XML-фрагменты.
- `methodology/` — рабочие правила «что преподаватель ожидает увидеть».
- `model/` — единый словарь сущностей, имён и GUID нашего проекта.
- `fragments/` — сборочные части нашего StarUML-проекта.
- `scripts/` — извлечение, сборка и проверка.
- `dist/` — итоговый монолитный StarUML-проект.
- `01_functionality/` — исходная рабочая версия первой части курсовой.

## Главное правило

**Имя и GUID сущности считаются частью контракта.**

Если один и тот же Use Case, класс, компонент или другой элемент показывается на нескольких диаграммах, мы не создаём новый объект только потому, что диаграмма другая. Сначала проверяем `model/registry.yaml`.

## Рабочий процесс

1. Определить требуемую диаграмму по `Порядок.txt`.
2. Открыть соответствующий раздел `reference/`.
3. Свериться с `methodology/`.
4. Проверить имена сущностей в `model/`.
5. Изменить сборочные фрагменты.
6. Собрать `dist/urban_development.uml`.
7. Запустить валидатор.
8. Только после этого открыть результат в StarUML и визуально проверить.

## Текущий статус

Первая модель функциональности уже существует. Проект имеет базовые StarUML Views, соответствующие `lending.uml`:

- Use Case View;
- Logical View;
- Component View;
- Deployment View.

Дальнейшие диаграммы должны добавляться в этот же проект, а не создаваться как независимые несвязанные `.uml`.
