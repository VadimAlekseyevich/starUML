# Курсовой проект — UML-моделирование Urban Development Generator

Этот репозиторий содержит материалы курсового проекта по проектированию информационной системы: исходную UML-модель в **StarUML 7**, методические указания преподавателя, пример оформленной курсовой работы и установленный порядок разработки моделей.

**Предмет моделирования:** [Urban Development Generator](https://github.com/VadimAlekseyevich/urban-development-generator) — отдельный программный проект, на основе которого выполняется курсовая работа. Здесь разрабатываются и документируются UML-модели этой системы. Исходный репозиторий приложения служит предметной областью и источником сведений о реализации; в рамках работы над данным репозиторием **изменять его не требуется**. Этот репозиторий не является исходным кодом самого генератора.

## Текущее состояние

В каноническом файле `urban_development_functionality.mdj` завершены первые два этапа курсовой:

- **Работа 1 — модель функциональности**: Use Case View описывает основные возможности предметной области.
- **Работа 2 — модель алгоритмов**: по замечанию преподавателя используется **выборочное, а не исчерпывающее покрытие**. В Logical View оставлены шесть содержательно важных диаграмм:
  - `DataManagement` — подготовка и контроль качества исходных геоданных;
  - `ScenarioConfiguration` — настройка и проверка сценария;
  - `ScenarioLaunch` — подтверждение и запуск сценария;
  - `GenerationExecution` — предметный алгоритм генерации;
  - `ScenarioComparison` — просмотр и сравнение вариантов;
  - `ResultExport` — экспорт результатов.

В Activity Diagram используются swimlane, Decision/Merge и, где существует реальная независимость ветвей, **Fork/Join**. Отдельные схемы для тривиальных действий и вспомогательных прецедентов не создаются только ради формального покрытия.

Следующий этап по `Порядок.txt` — **разработка модели классов системы**.

## Порядок дальнейшей работы

Последовательность ниже сохранена из [`Порядок.txt`](Порядок.txt):

1. Разработка модели функциональности системы — продолжить и проверить начатые диаграммы прецедентов, документирование элементов и связей.
2. Разработка модели алгоритмов системы — описать процессы и сценарии поведения соответствующими UML-диаграммами.
3. Разработка модели классов системы — сформировать логическую структуру сущностей, атрибутов, операций и отношений.
4. Разработка модели компонентов системы — показать состав программных компонентов и их зависимости.
5. Разработка модели размещения системы — показать узлы, окружение исполнения и размещение компонентов/артефактов.

Для содержания и правил оформления ориентироваться прежде всего на методичку преподавателя, а для структуры пояснительной записки и разумной глубины детализации — на приложенный пример работы. Не следует механически переносить из примера предметную область системы кредитования в данную модель.

**Принцип объёма курсовой:** преподаватель не требует исчерпывающего покрытия StarUML. Для каждого основного раздела целевой объём — примерно **5–6 наиболее показательных диаграмм**, раскрывающих главные проектные решения. Дополнительная декомпозиция создаётся только тогда, когда без неё теряется смысл алгоритма или архитектуры.

## Как открыть проект

На Windows с установленными **Git** и **StarUML 7** можно запустить `run_coursework.bat` из корня локального клона. Скрипт сначала подтягивает обновления командой `git pull --ff-only`, поэтому при локальных изменениях или отсутствии сети он может завершиться до открытия модели.

Скрипт использует заданный в нём путь к `StarUML.exe`, затем проверяет стандартные пути установки. Если StarUML установлен в другом месте, перед запуском задайте переменную окружения `STARUML7` с полным путём к исполняемому файлу. Альтернативно откройте `urban_development_functionality.mdj` непосредственно через StarUML.

**Граница работ:** изменения UML-моделей, документации и файлов этого репозитория допустимы в рамках курсового проекта; [`urban-development-generator`](https://github.com/VadimAlekseyevich/urban-development-generator) используется как отдельная система для анализа и не изменяется этой работой.
